02 / ARCHITECTURE

Calc Project 架构

calc-project一个以研究问题和可审计 Run 为中心的计算工作流插件
六个显式入口
ask-dnkcalc-setupcalc-rqcalc-to-speccalc-executecalc-review
持久权威与按需资源
manifest 定义插件身份与能力 skills/* 构成可调用入口 roster references / assets / scripts 与消费方共置或由共享消费者持有

调用边界

六个入口均为显式调用。$ask-dnk 仅在请求含混时路由；它不是必经前门，也不替用户自动调用 sibling。

资源所有权

单一 skill 使用的资料与该 skill 共置。只有至少两个活动 skill 实际消费的资源才进入插件级共享区，消费者必须声明精确相对路径。

渐进披露

SKILL.md 保留入口契约与路由，分支知识按需读取；脚本和运行资产不因进入发布包就自动进入模型上下文。

研究问题 RQ→设计权威 Spec→具体任务 / Run→执行与闭环

Calc Project 的关键约束：Spec 是 DAG、任务、Run、当前 Run、执行状态与闭环结论的唯一持久权威；calc-review 只生成瞬时只读判断，不建立第二套状态系统。

03 / BOUNDARIES

Calc Project 六个 Skill 的功能边界

六个入口按“路由、稳定配置、研究问题、科学设计、执行、瞬时审查”分工。它们只通过已落盘的权威文档和精确身份交接，不以会话记忆或隐式调用传递状态。

Skill何时使用唯一负责明确不负责 / 交给谁
$ask-dnk目标不清楚，或不知道应进入哪个入口。解析项目身份，选择一个目标 sibling 和一个候选 sibling，说明未完成的用户动作。不提供科学建议、不改写文档、不自动调用其他 skill；正确入口已知时直接使用该入口。
$calc-setup初始化或调整项目结构、数据边界、Tracker 或软件/集群 profile。稳定项目配置及其验证证据。不创建 RQ、Decision Ticket、Spec、任务或 Run；不提交作业、同步数据或验证可变 Run 环境。
$calc-rq创建、修订或检查一个研究问题，或逐一解决其 Decision Ticket。RQ.md 与临时 Decision Ticket 的生命周期；已闭环 Spec 对 RQ 的正式影响。不设计 Spec、不生成输入、不推进执行；科学设计与 DAG 交给 $calc-to-spec。
$calc-to-spec已接受的 RQ 需要形成一个主科学判断、任务 DAG、条件和验收/停止规则。当前 Spec 的科学承诺、任务声明、依赖、条件、验收与停止规则。不创建任务目录或 Run，不改物理数据或执行状态；Run 记录和推进交给 $calc-execute。
$calc-execute一个 ready/active Spec 需要准备、验证、提交、跟踪、同步、验收或闭环。从 Spec 推导 ready frontier，创建不可变 Run 快照，记录执行证据、Run 状态与当前 Run。不补猜科学值或修改 DAG/验收规则；设计歧义回到 $calc-to-spec，稳定配置问题回到 $calc-setup。
$calc-review一个已准备的精确 Run 在提交前需要独立、只读的预检。对当前链中相同输入、资源和目标环境返回 pass、pass_with_warnings 或 block。不写入 Spec/Run/缓存，不修复、不提交、不同步，也不授权提交；阻断项按归属回交 execute、to-spec 或 setup。

状态边界：RQ.md 是研究问题权威，Spec 是任务、DAG、Run 与闭环的唯一持久权威；review 返回只在当前执行链内有效。任何输入、资源、交接或环境变化都要求重新验证和审查。

05 / EXAMPLE

工作流示例：磁性交换参数到居里温度

目标是回答“该候选二维磁体的交换参数是否支持指定温区内的铁磁有序？”以下是一个 VASP → Wannier90 → TB2J → VAMPIRE 链的示例；它说明谁能推进什么，而不是替代具体科学参数和批准。

1

澄清与配置

$ask-dnk 在请求含混时路由；若项目目录、数据边界或集群 profile 缺失，$calc-setup 提出并在批准后写入稳定配置。

2

建立 RQ

$calc-rq 创建 RQ，明确材料、温区、成功判据和边界；需要决定磁序或比较标准时，用 Decision Ticket 逐一提案并获批。

3

发布可执行 Spec

$calc-to-spec 将被接受的判断写成一个 Spec：VASP 基态与 Wannier 交接、TB2J 交换参数、VAMPIRE 温度扫描的 DAG，以及每步输入、依赖和验收标准。

4

准备并审查 Run

$calc-execute 为 ready task 创建新的不可变 Run 快照，验证输入与 PBS；随后在同一执行链调用 $calc-review。只有相同快照得到 pass/pass_with_warnings 且提交范围已获授权，才能提交。

5

推进、验收与闭环

$calc-execute 依据日志、调度与产物证据推进 VASP→Wannier90→TB2J→VAMPIRE，按 Spec 验收。若需要改科学判断，回到 $calc-to-spec；若完成，先获批关闭 Spec，再由 $calc-rq 单独提议 RQ 结论影响。

RQ 与决定→Spec：DAG 与验收→每个 Run：prepare → review → authorized submit→证据验收与关闭

关键回路：$calc-review 若返回 block，不会留下新的状态；执行问题返回 $calc-execute，科学/DAG 问题返回 $calc-to-spec，稳定环境问题返回 $calc-setup。修复形成新快照后才可重新审查。

08 / TOKEN HEALTH

是否出现 Token 爆炸？

未发现结构性爆炸

六个入口没有在一次调用中自动加载全部 79 个运行时文件。入口正文合计 25,053 字节，参考资料按任务分支读取；真正显著膨胀的是本次开发与验收会话——13 项任务、45 个模型场景和 940 条工具调用累计了大量证据。这是测试编排成本，不等同于最终 skill 的日常上下文成本。

入口正文体积

calc-execute8,245 B
calc-to-spec6,440 B
calc-rq3,998 B
calc-review2,866 B
calc-setup1,981 B
ask-dnk1,523 B

约算而非 tokenizer 实测：按英文技术文本常用的 4 字符/token 粗估，六份入口全部同时读取约 6.3k token；正常单入口调用明显低于此数。

上下文分层

始终可见的入口正文25.1 KB
按分支读取的 references74.0 KB
运行资产与脚本99.9 KB
运行时总文件79

assets/scripts 是执行资源，不应因为“属于 skill”就自动进入模型上下文。风险评估要看一次具体路径实际读取了什么，而不是把发布包总大小换算成 token。

低风险

入口数量与显式调用

从九个入口收敛到六个，全部设置为显式调用，降低误触发和无关 skill 同时进入上下文的概率。

受控

渐进披露

后端、PBS、同步和修复规则放入 references，主入口通过具体任务分支读取，符合“公共步骤内联、分支知识外置”的结构。

需观察

calc-execute 热点

它承担 134 行入口、38.7 KB references 和多后端路由。复杂跨后端任务可能连续读取多份资料，是最可能产生上下文增长的区域。

结论与建议

  • 当前结论：没有证据显示日常 skill 调用发生 token 爆炸；有证据显示开发验收过程的上下文和证据量很大。
  • 不要误判：79 个包文件、282 KB 测试代码和历史 trace 不会自动成为一次运行的 prompt。
  • 重点监控：记录每次调用读取的 reference 文件数、累计字节和后端分支；尤其观察 calc-execute 是否跨分支过读。
  • 触发优化：若常规单后端请求持续读取无关后端资料，或入口正文继续增长，再按执行阶段/后端分支细化指针，而不是先拆成更多公共 skill。
