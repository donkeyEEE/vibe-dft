# Calc Review 流畅执行设计

## 目标

减少 `calc-review` 中不必要的强制形式和用户确认，让智能体在不改变科学意图、不扩大外部授权且不危及数据安全时，自动恢复执行流程。

## 模块职责

`calc-review` 仍是一个瞬时、只读的 prepared Run 检查过程。它判断当前快照能否提交，但不在评审过程中写入或修补快照。发现可修问题时，当前执行链直接回到拥有写入能力的步骤完成修复，然后重新 `prepare → validate → review`。

这不是强制的结构化交接接口。`calc-review` 不必返回固定 schema 的 finding 或 owner，也不必要求用户显式调用 sibling skill；它只需清楚说明证据、未满足条件和下一步，使当前执行链能够继续。

## 唯一停止条件

只有以下情况暂停自动流程并请求用户介入：

1. **新的科学判断**：继续执行必须创造或改变结构、磁序、科学参数、方法、科学数据来源、验收标准或停止标准，而现有批准材料不能唯一决定该选择。
2. **新的外部授权**：继续执行需要尚未覆盖的作业提交、资源或费用扩大、同步、取消、覆盖、删除或其他外部副作用授权。
3. **不可安全消除的并发风险**：当前 Run 仍可能被作业或其他进程写入，而且无法通过等待、使用新 Run 或其他非破坏方式安全继续。
4. **无法确定权威对象**：经过安全的自动检查后，仍无法唯一确定或调和当前 Spec、Task、Run 或权威来源。

显式用户暂停也必须遵守。缺少固定表格、机械错误、环境或稳定配置缺陷、可安全诊断的问题，以及存在多个等价技术实现，不构成用户介入条件。

## 默认恢复规则

不属于停止条件的问题默认由当前执行链恢复：

- Run-local 输入、脚本、PBS、路径、环境加载、资源渲染、handoff、checksum、文件保护、产品检查或打包错误，回到执行步骤修复。
- 稳定配置缺失或过期时，自动进入配置修复路径；只有修复需要新的外部授权或无法确定正确配置时才停。
- 根因尚未明确时，先进行安全、只读或可逆的诊断；只有诊断最终落入停止条件才停。
- 当前 Run 不适合原地修复时，按既有 provenance 规则创建新 Run，不因这一选择本身请求用户确认。
- 多个纯技术方案均忠实实现同一 Spec 时，智能体选择风险最低、改动最小、最容易验证的方案。

每次修改都会使旧快照判断失效。修复后必须重新准备、验证和评审。重复失败触发进一步诊断，而不是固定次数后机械询问用户。

## 科学证据而非固定形式

backend 规则声明必须证明的科学或安全事实，不普遍规定证明的展示形式。固定表格、逐项复述或特定命令只有在它们是建立该事实所必需时才使用。

对磁性 VASP，只有当磁序含义依赖原子身份或顺序时，才要求建立 prepared POSCAR 原子与 index-order `MAGMOM` 的无歧义映射。逐原子表是一种可选证据形式，不是普遍要求；无法验证映射才阻止提交。

其他适合相同简化策略的规则包括：

- 将逐文件或逐字段的固定报告要求改成针对风险的可复核证据；
- 将机械修复的逐次授权改为既有执行范围内的自动恢复；
- 将固定工具或命令要求保留为产生特定不可替代产物时的约束，否则允许等价实现；
- 将配置缺失、可诊断错误和纯技术方案选择从“停下询问”改为自动处理；
- 保留精确快照、科学意图、不可逆操作、外部提交和数据 provenance 这些结果不变量。

## 修改范围与验证

修改 `calc-review` 的主流程、pre-submit/PBS 规则和相关 backend 规则；同步移除 `calc-execute` 中“只推荐 sibling”“简单修复必须逐次获得授权”等冲突语义。保留用户已有的未提交修改，并只编辑必要段落。

契约测试应验证：文档只列出上述停止条件；执行缺陷默认恢复；评审不要求结构化 finding/owner；磁性逐索引表不再是普遍要求；修改后仍需 fresh review；科学判断与新增外部授权仍会停止。
