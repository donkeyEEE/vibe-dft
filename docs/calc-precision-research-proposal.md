# 让计算精度服务研究判断：Calc Project 修改建议

日期：2026-10-07

更新：2026-10-08

状态：六项修改原则均已确认，已实施到插件；验证结果见文末。本文件不作为独立 ADR。

## 已确认的讨论结论

2026-10-07，第一项参数归属原则已获用户确认：Spec 主要确定科学用途、方法条件和必要的比较约束；普通数值参数由执行阶段依据适用证据选择并记录。选择可能改变研究判断、适用依据不足或用户明确指定时，返回设计或遵循已有明确承诺。

2026-10-08，第二项字段说明已获用户确认，采用简洁表述：Purpose 为“本任务要回答什么，以及答案如何影响研究”；Acceptance 为“什么证据足以完成该任务”。方法、参数和模型假设写在已有上下文中，精度与不确定性只在需要时补充。此次确认针对 Purpose、Acceptance，不包括另行修改 Blocked by、Condition 或状态体系。

2026-10-08，第三项已获用户确认，直接采用参考项目的两种方式：“设计时安排已知重要的比较；执行中出现具体迹象后，再追加对应计算。”此次确认不包括另设阶段流程或统一通过、淘汰门槛。

2026-10-08，第四项已获用户确认：“后端准备任务所需的输入和产物；诊断计算与图件按任务要求安排。”执行说明、评审和模板须联动修改；目标用途必需的验证及明确的方法有效性检查继续保留。

2026-10-08，第五项已获用户确认：“违反任务承诺、存在明确的方法或执行缺陷时阻止提交；进一步改进的建议按当前用途处理。”阻断发现须说明依据；评审发现 Spec 未预见、可能使目标判断无效的具体问题时，仍返回设计处理。

2026-10-08，第六项已获用户确认：“任务完成后，说明结果如何影响研究判断，并据此推进、调整或结束后续计算。”已声明的条件按结果判断；改变任务或新增科学比较返回 Spec 设计，方法失败走排障，可靠的负面科学结果用于研究取舍。无需新增逐 Run 独立复审。

六项原则均已确认。以下保留修改前的问题分析、参考项目对应与细化建议；实际修改和验证记录见文末。

## 目标与分析范围

本建议解决使用 Calc Project 时出现的一类偏移：研究本来要区分机制、选择候选或判断性质是否成立，任务却逐渐围绕参数依据、收敛测试和质量证明展开，科学判断被推迟。

目标是：**每项科学计算对应一个可能改变研究判断的问题；精度投入服务于这个判断；后续计算由研究需要和观测证据触发。** 输入生成、文件交接等实现步骤说明其支持的科学用途即可，不必为每个技术动作另造研究问题。

本次依据当前插件文档、执行模板和参考项目的公开记录提出建议。文档冲突可以直接核对；“这些冲突使智能体增加了计算或暂停主线”属于待验证的行为解释。尚未检查具体用户项目的 RQ、Spec、Run 和对话日志，不能据此断言每次精度偏移都有同一根因。

参考项目为本地 [compensated-magnet-ledger](../reference/compensated-magnet-ledger/README.md)，读取快照为 `45551de5fac4e69de3e03c420b31abb335d73ef4`。本文链接指向本地克隆，不把该项目的数据和代码加入插件发布资源。

## 参考项目给出的证据及其边界

参考项目研究 YBaMnFeO₅ 和 KV[Cr(CN)₆] 的补偿磁性与自旋分辨带边。它的任务记录展示了按用途分配计算的做法：

- PBE+U 承担结构优化和主要扫描；HSE06 在优化结构上检查关键结论，而非承担全部结构优化。
- PBA 的 NSCF 网格由候选的 7³ 改为 8³，使网格包含 X、L 等重要点；选择依据关联到带边用途。
- U 使用二维扫描，因为两种离子 U 的相对偏移可能影响带边；这不是对所有材料都要求全面参数扫描。
- 初步检查有预先记录的通过与淘汰标准；缺陷任务安排在初步通过后。水合带边若接近判断边界，再追加 PDOS 分析。
- 自由铁磁参考态发生电荷转移后，增加固定总磁矩参考计算，以恢复交换比较所需的状态。
- YBaMnFeO₅ 的目标性质依赖 Mn/Fe 有序，因此安排有序—无序计算；结果使候选降级，研究转向配位化学固定子晶格的材料。

可核对来源：

- [PBA 工作记录：精度设定、通过与淘汰标准、适应性调整](../reference/compensated-magnet-ledger/materials/KV_Cr_CN6/working_notes/pba_README.md)，第 3–5 节。
- [PBA 任务参数记录](../reference/compensated-magnet-ledger/materials/KV_Cr_CN6/analysis_data/gate0_manifest.json)。
- [YBaMnFeO₅ 档案：失败判定与带入下一轮搜索的教训](../reference/compensated-magnet-ledger/materials/YBaMnFeO5/AGENT_DOSSIER_2026-10-02.md)，第 V 节；第 0、3 节部分原始主张已经被更正。
- [当前账本：设置、结果、更正与方法问题](../reference/compensated-magnet-ledger/LEDGER.md)。旧工作记录中的数值和待完成状态不代替此账本。

参考项目不能作为“所有精度处理都已正确”的范例。原水合 HSE06 曾未完成精确交换外循环，却被标记收敛，后续 F2 才补跑完成；含水空位及部分阳离子排列的结构未充分弛豫；HSE 带边来自较稀的 SCF 网格；SOC 结果最终未作为可靠证据使用。它还省略了较大研究活动的早期任务。因此应借鉴其任务与判断的联系，同时保留真实的计算有效性检查。

## 修改一：统一科学承诺与执行参数的归属

### 问题

[calc-to-spec](../plugins/calc-project/skills/calc-to-spec/SKILL.md) 允许有确定依据、不改变科学含义的实现值留给执行；[VASP 科学设计](../plugins/calc-project/skills/calc-to-spec/references/backends/vasp.md) 只在影响解释或可比性时要求记录 ENCUT、k 密度、展宽。

但 [VASP 通用执行要求](../plugins/calc-project/skills/calc-execute/references/backends/vasp/common.md) 要求 Spec 先确定这些值，否则返回设计。两种规则不一致，可能使普通实现选择反复回到 Spec，或使智能体为了证明参数依据而追加测试。

### 参考项目对应

PBA 工作记录将结构优化设置为 110 Ry，HSE 单点为 90 Ry；解释包括应力对截断的敏感性、赝势建议和短 C≡N 键。NSCF 网格考虑带边所在的采样点。这些事实支持“按用途选择设置”，不证明这些设置可以直接迁移到其他材料或 VASP。

### 建议改法

替换 VASP common 的无条件前置列表，建议表述为：

> Spec 确定计算类型、研究对象、方法条件和必要的可比性要求。未显式指定的执行参数，由 calc-execute 依据当前用途、适用计算规范和已有证据选择，记录在 Run inputs 中。选择会改变科学含义，或现有依据无法支持目标判断时，交回 calc-to-spec。

参数归属依用途判断，不建立固定的“科学参数名录”。U 在研究交换对 U 的依赖时是研究变量，在已选模型中是方法条件；k 网格通常用于数值采样，但在微小能量差研究中也可能构成必须统一的比较承诺。

Spec 已指定的数值、方法和可比性条件继续有效。模板仍是实现基线，不能仅因存在模板就宣称其数值适用。已有同类验证、软件建议及当前物理尺度可以支持选值，不要求先建立完整的材料专属参数档案。

### 涉及文件与完成标准

- 主要修改：VASP 执行 common。
- 联动核对：VASP 设计、Spec 模板参数归属说明、VASP 评审参考。
- 完成标准：Spec 给出了明确科学用途和方法条件，已有依据支持执行设置时，执行者可以完成选值与记录；改变磁序、模型等科学含义的选择仍返回设计。

## 修改二：用 Purpose 与 Acceptance 连接计算和判断

### 问题

[Spec 模板](../plugins/calc-project/skills/calc-to-spec/references/spec-template.md) 已有判断、Purpose、Acceptance 和 Condition。无需再加“精度说明表”或额外质量档位，但需让字段的写法更容易产生有研究作用的任务。

### 参考项目对应

项目不是只要求“能带算完”，而是判断两侧带边是否同自旋、窗口是否达到目标。原子有序计算则用于判断目标结构在合成温区是否可形成。这些任务都存在影响后续路线的结果分支。

### 建议改法

在模板字段说明中明确：

> Purpose：本任务要回答什么，以及答案如何影响研究。
> Acceptance：什么证据足以完成该任务。

方法、参数和模型假设写在已有上下文中；精度与不确定性只在需要时补充，避免在两个字段中重复展开。

科学任务可写为：

```text
Purpose: 判断 Mn/Fe 有序能否在合成中形成，决定是否继续推进该候选。
Acceptance: 比较有序温区与阳离子可重排温区，给出可达性判断或明确未决原因。
```

这类完成要求只适用于明确的探索任务；不能用于放宽已有 Spec 的确定性验收。没有取得所需观测、计算本身无效或关键证据缺失时，也不能以“存在不确定性”为由完成任务。

对输入准备、接口产物等步骤，说明支持的研究任务及交接要求即可。设计不强制为每个任务列出全部可能结果，也不强制量化所有阈值。

### 涉及文件与完成标准

- 主要修改：Spec 模板字段说明。
- 联动修改：calc-to-spec 起草步骤引用同一说明，减少重复原则。
- 完成标准：从 Purpose、Acceptance 和已需要的 Condition 能看出这项科学任务为什么值得算、何时已足够；不会默认生成与目标无关的精度清单。

## 修改三：精度追加由研究用途和证据决定

### 问题

[研究推理指引](../plugins/calc-project/skills/domain-research/references/research-reasoning.md) 已要求复用适用设置、按判断安排投入。应增强其完成标准，而非在各 backend 重复“必须严谨”或“禁止过度验证”。

### 参考项目对应

参考项目的 U 扫描用于检查离子相对能级；声子位移力使用更严格的 SCF 阈值；固定总磁矩任务由参考态发生电荷转移触发。三者分别对应模型敏感性、数值分辨需求和模型参考态失效，不能混为一类收敛问题。

### 建议改法

在研究推理指引中统一记录：

> 设计时安排已知重要的比较；执行中出现具体迹象后，再追加对应计算。

例如，已知两种离子的 U 会影响相对能级，设计时安排二维 U 扫描；铁磁参考态发生电荷转移后，追加固定磁矩计算；水合结果接近判断边界时，追加 PDOS。采用的理由简要写在现有 Purpose 或上下文中，不新增报告 schema 或阶段流程。执行中的科学追加仍沿既有设计和授权规则处理。

“文献有其他取值”“还有更密网格”“没有本材料专属收敛曲线”不是独立的研究目的。它们需要结合当前用途判断。误差也不必强行转成一个已知标量；可依据相关差值变化、适用经验或针对性比较判断，但 SCF 阈值本身不能等同于物理量误差界限。

### 涉及文件与完成标准

- 主要修改：research-reasoning.md，在已有参数选择段落中替换和整合，避免追加重复章节。
- docs/research-thinking.md 保留概念说明，不复制执行规则。
- 完成标准：智能体能区分数值采样、模型敏感性与方法有效性，并据当前判断选择投入；不会用更小电子阈值掩盖模型或结构错误。

## 修改四：清理后端和模板里的无条件验证产物

### 问题

Wannier90 的 [设计参考](../plugins/calc-project/skills/calc-to-spec/references/backends/wannier90.md) 按用途选择 WOUT 和拟合证据；[执行参考](../plugins/calc-project/skills/calc-execute/references/backends/wannier90/common.md)、[评审参考](../plugins/calc-project/skills/calc-review/references/backends/wannier90.md) 和 [PBS 模板](../plugins/calc-project/skills/calc-execute/assets/templates/wannier90/run.pbs.template) 却统一要求范围文件、重排能带、DOSCAR、绘图脚本、band 数据和拟合图。

这里不仅是文案问题：模板实际将缺失文件判为失败，并无条件绘图。只改 skill 文本无法改变行为。

### 参考项目对应

PBA 工作记录明确：初步水合检查没有 PDOS，若变化接近边界，再追加 projwfc。应借鉴“证据按用途选择”，但不能据此认定任一 Wannier 用途都无需检查拟合；交换或带边用途可能确实依赖相关质量证据。

### 建议改法

已确认的规则为：

> 后端准备任务所需的输入和产物；诊断计算与图件按任务要求安排。

区分完成计算或下游接口所需的产物与特定诊断产物。前者按实际 Task 和交接契约准备；拟合图及其输入仅在任务要求该比较时生成和检查。

实现时同步调整准备、复制、PBS、日志、产物检查和评审。可按 Task 渲染具名命令及产物要求，或采用最小的诊断开关；具体方案依据现有模板结构决定。不能仅删除最后的图件检查而仍执行缺少输入的绘图命令，也不能因为某文件名含有“图”就认定它可选。

保留冻结态数超过 NUM_WANN 等明确有效性检查、批准的子空间和窗口、不可变来源，以及目标用途所需的充分拟合证据。

### 涉及文件与完成标准

- Wannier 设计、执行、评审参考。
- wannier90/run.pbs.template 与 wannier-run.env.template；检查实际输入准备消费者。
- 顺带核对 TB2J 执行中无条件要求 VAMPIRE 产物是否符合 Task 用途；这是候选检查项，尚未证明所有场景都存在冲突。
- 完成标准：要求拟合证据的任务仍完成比较并校验；没有图件用途的任务不会因通用绘图输入缺失失败；必需接口和有效性检查不减少。

## 修改五：评审发现绑定承诺或目标判断

### 问题

[calc-review](../plugins/calc-project/skills/calc-review/SKILL.md) 要求修复任何可修复缺陷。若“更精细会更好”也被当作缺陷，独立评审就可能不断扩大任务。当前提交前检查已围绕 Spec 一致性展开，应把缺陷的判定依据补清楚。

### 参考项目对应

参考项目既有通过标准，也保留已知局限。HSE 网格较稀被记录为结果限制；水合 HSE 外循环未收敛则需要补跑。两者提醒我们：精度改进建议与真实完成缺陷应依据用途和证据区分，不能一概放过或一概阻断。

### 建议改法

在评审通过条件处明确：

> 违反任务承诺、存在明确的方法或执行缺陷时阻止提交；进一步改进的建议按当前用途处理。

阻断发现须说明违反的承诺或具体缺陷及其证据。评审发现 Spec 未预见、可能使目标判断无效的具体问题时，仍返回设计处理。

评审可以发现 Spec 未预见的科学有效性问题。需要改变设计时返回 calc-to-spec；执行缺陷交由执行修复。缺少未要求的图件或存在另一种等效实现，本身不构成阻断。

沿用 pass、pass_with_warnings 和现有返回路径，不增加审查类别、评分或批准缓存。用户明确精度要求继续有效。

### 涉及文件与完成标准

- 主要修改：calc-review/SKILL.md 的通过条件。
- 联动核对：pre-submit.md 与适用 backend 检查，避免另设不同门槛。
- 完成标准：每项阻断有可核对的承诺或有效性依据；参数优化建议能按用途处理；输入错误、上游错误及会破坏结论的设置仍被阻断。

## 修改六：结果返回后，重新判断下一项投入

### 问题

[calc-execute](../plugins/calc-project/skills/calc-execute/SKILL.md) 已在解释结果时加载 domain-research，但指针主要强调概念和术语。[任务推进](../plugins/calc-project/skills/calc-execute/references/task-advancement.md) 也已经禁止临时增加质量门禁。需要把这些规则用于持续解释结果，减少执行只关注 Run 状态的风险。

### 参考项目对应

YBaMnFeO₅ 的有序温度结果改变了“材料能否实现”的判断，并促使下一轮寻找配位化学固定的子晶格。任务完成产生负面结果，同样推进研究；不必继续把理想晶体的所有性质算到最精细。

### 建议改法

调整 execute 的 domain-research 调用指针，使结果解释包含研究取舍，而非每次提交都重新加载它。在 task-advancement 的验收后说明：

> 任务完成后，说明结果如何影响研究判断，并据此推进、调整或结束后续计算。

已声明的条件直接按结果判断；需要改变任务、验收或增加科学比较时，交回 calc-to-spec，沿既有设计模式处理。方法失败走排障；可靠的负面科学结果用于研究取舍。

不增加每个 Run 的独立科学复审。普通准备和状态查询照常推进；取得会影响判断的结果时再做相应分析。不能私自跳过 always 任务、放宽 Acceptance、取消活动作业或改写 concluded Spec。需要变更时沿现有授权规则处理。

设计阶段依据已知风险安排 Condition：初步性质支持候选时再做昂贵验证，发现具体数值边界时再加精度比较。并非所有任务都必须串行；彼此独立、价值已确定的计算仍可并行。

### 涉及文件与完成标准

- calc-execute/SKILL.md 的结果解释指针。
- task-advancement.md 的验收与推进说明。
- calc-to-spec 起草步骤和 Spec 模板的 Condition 说明按需联动。
- 完成标准：负面结果可以完成任务并影响后续条件；未声明的新研究选择返回设计，不以技术排障替代科学取舍。

## 建议实施顺序与范围

1. **先消除直接冲突。** 修正 VASP 参数归属；联动修正 Wannier 执行、评审、模板的条件产物；澄清评审缺陷判定。这些问题有直接的文本或代码证据。
2. **再改善研究推进。** 调整 Purpose/Acceptance 的说明、研究推理指引和结果解释指针。规则放在唯一负责的位置，其他入口用准确的调用条件连接。
3. **核对行为与发布资源。** 检查路径、消费契约、脚本和插件发布包，再运行下述场景。若行为仍偏移，结合真实使用记录定位；不默认继续加禁令。

本建议落实 ADR-0020、ADR-0021 的既有方向。实施时可根据最终变更决定是否需要新的 ADR；本文不是已接受的领域决策。新增版本号时按仓库要求记录 CHANGELOG；本讨论稿不引入版本号。

不新增 skill、精度档位、状态、Tracker 字段、逐 Run 研究审批或重复日志。旧 Spec 继续按现有承诺执行，本修改不批量放宽旧验收。源仓库安装、发布及外部计算提交不属于本次文档工作。

## 验证方案

文本和模板一致性检查与少量行为场景分别验证不同问题。模板修改可在临时目录用替代可执行文件检查命令分支、必需输入与条件产物，不必为规则维护提交真实集群计算。

| 场景 | 提供的证据与要求 | 应观察到的行为 |
|---|---|---|
| 适用设置已足以支持排序 | Spec 未固定 k 网格；已有相关采样比较支持当前用途 | 执行选值、记录并推进，不生成全参数扫描 |
| 排序处于分辨边界 | 相邻采样下差值变化与目标能量差相当 | 针对性比较或按设计保留不确定性，不能宣称排序可靠 |
| 模型敏感性影响判断 | 合理 U 变化导致目标性质改变 | 将相关模型比较纳入设计，不用收紧 SCF 阈值替代 |
| 探索任务产生负面结果 | 所需观测有效取得，下游 Condition 为假 | 探索任务可完成，下游按现有条件规则处置 |
| 未要求拟合图 | Task 的接口与用途有充分证据，不依赖图件 | 不因未声明绘图输入缺失失败 |
| 要求拟合图 | Task 明确需要特定能区的 DFT/Wannier 比较 | 准备相应输入、生成比较、按指定用途验收 |
| 方法存在有效性缺陷 | 冻结态数超过 NUM_WANN，或指定磁序映射错误 | 阻断并修复或返回设计，不能作为普通精度建议略过 |
| 用户已明确更高精度 | Spec 接受并记录具体要求 | 执行原承诺，不能引用剪枝原则自行放宽 |
| 结果要求缩减 always 任务 | 新结果降低后续价值，但任务尚无停止条件 | 交回设计处理，不私自跳过或追加研究任务 |

检查行为时观察实际任务选择、返回路径和产物，不以文档中出现“剪枝”二字作为通过。行为样例是维护验收材料，不进入每次科研计算的强制检查清单。

## 对修改效果的判定

预期效果是减少实现参数返回设计、无用途的诊断产物和无证据的追加验证，同时保留明确有效性检查、可比性、来源和用户要求。是否减少了实际研究偏移，需要用真实项目的修改前后轨迹确认。

如果修订后仍出现精度掩盖问题，优先检查最初 Spec 是否已将所有验证写成无条件承诺，以及执行是否违反“按已记录要求验收”。二者分别需要修正设计与执行行为，不能用同一份额外检查清单解决。
