# 进度跟踪表契约

## 职责与旧项目

`calc-setup` 拥有项目 AGENTS 维护约定的写入和迁移，遵循其现有授权规则。
其他技能直接维护派生跟踪表；项目约定缺失时使用本契约处理跟踪表，
将稳定项目规则的补齐交给 `$calc-setup`，不自行修改项目 `AGENTS.md`。
`show-cot` 可以继续查询或重建跟踪表，并说明项目规则尚待配置；规则补齐不作为只读查询的前置条件。
首次创建跟踪表时确保根 `.gitignore` 包含 `/.calc-project/`，只追加缺失规则。

## 项目 AGENTS 约定

由 `calc-setup` 在初始化或维护项目时，将以下约定写入项目 `AGENTS.md`，保留其他项目规则：

> **进度跟踪表维护**：`.calc-project/tracker.json` 是 RQ → Spec → Task → Run 的派生索引。
> 四类对象中任一对象的状态发生改变，都必须在写入权威记录后立即直接更新进度跟踪表中对应条目，
> 并检查两者一致，完成后再继续执行或交接。新增、删除、重命名、归属或路径变化，以及 current Run
> 切换时也同步维护。以 RQ.md 和 Spec 为权威，保留无关条目；索引更新失败时明确报告未同步，
> 在恢复工作时优先修复。由智能体直接编辑 JSON，无需统一更新脚本。
> 索引缺失或损坏时从全部权威记录重建；日常只更新受影响分支。存在其他写入者时，写入前重读
> 最新进度跟踪表并合并各分支变更，避免覆盖他人更新。
>
> 进度跟踪表顶层使用 `schema_version: 1`、`updated_at`（含时区的更新时间）和 `rqs` 数组。
> RQ 条目包含 `id`、`title`、`status`、`source`（项目相对 RQ.md 路径）及 `specs`；
> Spec 条目包含 `id`、`title`、`status`、`source`（项目相对 Spec 路径）及 `tasks`；
> Task 条目包含 `id`、`title`、`status` 及 `runs`；Run 条目包含 `id`、`status` 和布尔值 `current`。
> 各层子对象使用数组，空集合写为 `[]`；ID 仅在父范围内唯一，以 RQ 的 source 和完整父链定位条目。
> 状态照录权威记录，不通过子对象状态推断父对象状态，不复制科学正文或执行日志。
> COT 查询默认读取进度跟踪表；仅在缺失、异常、已知未同步或用户要求核对时回查相应权威记录。

空项目的进度跟踪表为 `{"schema_version": 1, "updated_at": "<带时区的时间>", "rqs": []}`；
已有项目只有在覆盖全部配置范围后才能视为完整索引。无法读取的记录应报告为未完成重建，
不得用空数组冒充完整项目。
