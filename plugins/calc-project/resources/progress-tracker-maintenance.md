# 进度记录维护契约

字段与权威边界见[进度记录契约](progress-tracker.md)。由智能体直接编辑 JSON，无需统一更新脚本。
`calc-setup` 按其入口授权维护项目约定；其他技能维护派生记录。

## 更新

状态、条目增删、名称、归属、路径或 current Run 发生变化后，先写权威记录，再立即更新所属
RQ 的记录并检查一致性，完成后才继续执行或交接。日常只更新受影响 RQ，保留无关条目；
跨 RQ 移动时更新源和目标记录。同一 RQ 有其他写入者时，写入前重读最新记录并合并变更。
更新失败时报告未同步，并在恢复工作时优先修复。

首次创建记录时，在根 `.gitignore` 追加其精确项目相对忽略规则，以 `/` 开头，例如
`/01-main/01-rqs/RQ-001-example/tracker.json`，保留其他规则。
创建 RQ 时建立记录，尚无 Spec 时 `rq.specs` 为 `[]`。

## 重建与缺失约定

记录缺失、损坏或需要核对时，仅从该 RQ.md 及其全部已发布 Spec 重建。
无法读取权威记录或覆盖不全时，明确报告未完成重建及未同步范围。
项目总览枚举实际 RQ 目录，不能仅搜索现有 `tracker.json` 而遗漏未建立记录的 RQ。

项目约定缺失时，先按本契约维护记录，将稳定规则的补齐交给 `$calc-setup` 按其授权规则处理。
`show-cot` 可继续查询或重建并说明规则待配置，不自行修改项目 `AGENTS.md`。
