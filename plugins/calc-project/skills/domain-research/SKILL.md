# Domain Research

本技能以物理因果链和计算剪枝指导研究推理，维护研究术语的名称、含义及适用范围，
并在产出或修改研究文档时清理冗余表达、保留原意与作者语气。
研究逻辑由本技能指导；所在 Calc 工作流按其授权规则采纳建议，并负责研究记录的组织与写入。加载时读取
[科研通用术语](references/research-context.md)。

## 工作流程

1. **确定术语来源。** 读取项目根 `CONTEXT.md`（项目上下文）和选定 RQ 的
 `RQ-CONTEXT.md`（RQ 上下文）。涉及插件流程概念时，按需读取
 [共享领域术语](../../resources/project-context.md)。
2. **分析研究逻辑与取舍。** 讨论机制、设计 RQ/Spec、解释结果或组织汇报论证时，读取
 [研究推理指引](references/research-reasoning.md)，用物理因果链分析需要验证的问题，
 用计算剪枝判断相关自由度、参数探索和精度投入。依据当前问题选择有用的分析，
 将发现转化为具体的解释、关键比较或取舍建议；完成标准是这些建议能说明其物理依据
 及对核心结论的影响。单纯术语整理或文字润色沿用原有科学判断。
3. **对齐用词。** 找出当前讨论或草稿中的关键研究术语，优先使用项目及 RQ 已确认的名称和
 定义。  
 当前材料明确显示判断措辞与内容不符，或调用方要求审查时，检查“可能、支持、证实”等措辞，
 必要时调研清楚并调整表达。
 内置定义提供通用参照，不能覆盖已确认的项目语境。  
 对来源中已有但未入清单的术语，保留原词并在需要时解释；用完整描述表达尚未命名的关系。
4. **处理偏移与歧义。** 含义清楚时直接改为已对齐的表述，并检查同一文本中的其他用法。
 与现有定义冲突时，先判断是否只是材料、尺度、条件或研究手段不同；确有不同含义，
 或名称会改变研究判断时，列明候选含义及影响，请研究者裁定。术语含义无法确定时
 保留原词，并指出具体歧义；术语修订保持原有科学判断。
5. **维护可复用术语。** 收录当前研究中需要持续使用和统一含义的关键术语。
 先查已有条目，确定新增还是更新。首次收录由研究者确认名称和含义；讨论中已明确认可的
 条目直接写入，无需再次确认。同义措辞修订可直接更新，含义或适用范围变化时先讨论确认。
 确认后当场写入 `RQ-CONTEXT.md`，记录名称、简短定义和适用范围；未确认的留在当前讨论中。
 写后核对条目与已确认内容一致。
6. **通读并改写。** 产出或修改研究文档时，读取
 [研究文档表达规则](references/research-writing.md)，按其中规则完成改写。
 原文题名、直接引文和作者命名可保留原词，
 确有必要的新词须解释其含义。
7. **核对原意与交付。** 对照输入和可用上下文，核对术语、数值、条件、否定、比较及逻辑关系、
 判断强度和引用，确保改写没有新增或遗漏信息。完成标准是表达自然、术语准确、原意完整。
 交付最终文本；修改文件时只写入最终文本并简述修改，保留代码、命令、路径、元数据和链接目标。
 仍影响理解且无法从上下文解决的歧义，列为具体待裁定事项交回调用方。

## 术语文件

`RQ-CONTEXT.md`（RQ 上下文）由本技能维护。首次创建 `RQ-CONTEXT.md` 时，只收录本研究
已确认的关键术语。项目与插件已有的定义按需读取，不复制到 RQ 术语清单。
文件结构为标题、简短说明、`## Language`；条目以 `**术语（可选英文名）**:` 开始，
随后用一两句说明含义和适用范围，必要时附 `_Avoid_:`。

条目模板（英文名和 `_Avoid_:` 行按需保留）：

```markdown
**<术语名称>（<英文名>）**:
<用一两句说明该术语在当前研究中的含义及适用范围。>
_Avoid_: <需要避免的别名或易混用法>
```

## 记录与决策边界

项目共用概念及项目根 `CONTEXT.md` 交 `$dev-engineering:domain-modeling` 维护；
本技能指导机制解释、关键比较、证据选择、验证投入与研究条件，
将建议及依据交回所在 Calc 工作流，按其设计模式和授权规则采纳并记录。
`RQ-CONTEXT.md` 只保存已确认的术语；科学假设、设计决策、验收要求和结论写入对应研究记录。
