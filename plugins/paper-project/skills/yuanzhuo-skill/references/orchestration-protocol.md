# 人格席位编排协议

创建、继续、替换或结束人格席位时使用本协议。主持人管理流程和事实；子 Agent 独立承担人格发言。

## 共享简报

在创建席位前整理一份相同的共享简报：

- 用户的原始议题；
- 用户希望探索、压力测试或决定什么；
- 已知约束和不应假设的条件；
- 独立观点或圆桌交锋模式；
- 已核验的事实包及其来源；
- 输出语言和深度。

事实包只写各席位共同使用的事实，不混入主持人的建议。时效性事实没有核实时，先完成核实或明确标记未知。

## 创建人格席位

每个席位使用一个独立子 Agent。给子 Agent：

1. 索引中 `persona_file` 给出的精确资源路径；
2. 共享简报；
3. 当前轮次任务；
4. 输出合同。

`persona_file` 始终相对本技能的 `references/` 目录解析。要求子 Agent 在回答前完整读取该文件，只在当前问题需要时读取同一人格目录中的其他引用。一个席位只读自己的人格目录。子 Agent 应区分资源支持的已知立场、框架推断和未知范围，不把推断伪装成真实语录。

第一轮输出合同：

- 核心判断；
- 推理链与关键假设；
- 对用户的建议；
- 最大不确定性；
- 想向另一种视角追问的一个问题。

## 盲开场

在可用并发范围内同时启动所有席位。首轮不给任何席位其他人的答案，也不把先返回的观点加入后返回席位的上下文。所有席位收到完全相同的共享简报。

收到全部结果或明确失败状态后，主持人按席位分别呈现，不按返回顺序暗示优先级。然后总结真实共识、最重要的前提分歧、未核实事实和下一轮可追的问题，并暂停。

## 持续交锋

后续轮次继续使用同一个子 Agent，保留其前文和立场。只向它转发：

- 另一席位带名字标注的原话；
- 主持人的中性问题；
- 用户新增的事实或约束。

转发保持原意，不替对方强化或弱化论点。每次只推进一个核心分歧；完成一次交换后回到用户。

## 定向询问

用户要求 A 询问 B 时：

1. 把 B 的相关原话交给 A；
2. 让 A 提出一个最能暴露关键假设的问题；
3. 把 A 的问题原样交给 B；
4. 把 B 的回答原样交回 A；
5. 允许 A 回应一次；
6. 主持人总结双方在哪个前提上分叉、是否有立场更新。

问题、回答和回应必须来自对应席位。主持人负责中继，不代写任一环节。

## 容量与轮换

默认使用 2–3 个人格席位。主 Agent 之外的并发容量不足时：

1. 告知实际可用容量；
2. 推荐保留最相关且差异最大的席位；
3. 用户坚持更多人物时，使用明确标注的轮换嘉宾；
4. 不把分批回答描述成同时讨论。

新增嘉宾先读取此前的主持摘要和必要原话，并明确它没有经历之前各轮。离席或被替换的人格停止接收后续消息。

## 漂移与失败

发现人格忘记身份、混入另一人格或退回通用助手时，进行一次校准：重新提供人格路径、共享简报、该席位自己的先前立场和当前任务。第二次仍漂移则终止并重建席位，向用户说明连续性已经中断。

席位超时、失败或没有返回时，标为不可用。只有用户要求重试，或一次安全重试显然符合当前请求时才重试；停止条件是一轮重试。主持人继续其他席位或请用户缩减，始终保留缺席标记，不写替代答案。

## 主持综合

综合时保留：

- 每个人格的当前立场；
- 多席位独立得到的真实共识；
- 价值冲突与事实错误之间的区别；
- 分歧依赖的假设；
- 谁更新了什么立场；
- 未核实事实和未知范围；
- 用户下一步最值得选择的控制或行动。

除非用户要求裁决，不宣布赢家。少数意见有更强理由时如实保留，不用多数票代替判断。

## 轮次与结束

一次执行只完成盲开场或一轮交锋，然后把控制权交还用户。用户要求总结时停止新增交锋；用户要求结束、替换席位或达到约定停止点时，终止对应子 Agent。

一轮完成的检查条件：每个请求席位已经返回或被明确标记失败；人格输出和主持总结清楚分开；核心分歧没有被压成模糊共识；用户得到下一步控制选项或最终纪要。
