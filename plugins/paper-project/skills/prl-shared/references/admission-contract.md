# 准入接口

本接口是外部 `research-knowledge` 正式知识写入的单一规则来源。Cangjie 是当前受支持的正式写入流程；AI 提出候选和变更，人类确认后才从 `candidates/cards/` 或 `candidates/templates/` 晋升到正式卡片或模板并更新索引。

## 输入

每个候选必须提供：

- 可访问的来源内容及足以重新识别来源的信息；
- 人类说明的知识意图；
- 一个原子知识对象及其核心陈述；
- 建议的 `name`、`type`、tags 和写入动作；
- 来源定位，以及来源具体支持的卡片内容。

## 准入门禁

所有候选都必须满足：

1. **来源验证**：Agent 已核对来源内容；只有书目信息不构成支持。
2. **知识价值**：候选不是孤立摘录、空泛常识或未经支持的推断。
3. **原子性**：一张卡只承载一个知识对象，但可以完整说明其条件和边界。
4. **一致性**：候选不复制现有卡片，也不静默覆盖冲突或同名异义。
5. **索引兼容**：名称、类型、tags、状态、关系和目标目录符合对应索引。
6. **人类确认**：人类确认候选、类型、tags 和写入动作。

通用卡还必须能够服务两个或以上 skill，并通过证据、迁移性和非平庸性检查。物理卡面向未来检索，不要求已有多个消费者，但必须通过来源支持、知识价值、原子性和现有物理卡一致性检查。

## 写入动作

- `new card`：创建不存在的知识对象。
- `append source`：追加支持同一知识对象且不改变现有正文的来源。
- `revise card`：更新解释、条件、边界、核心陈述或状态。
- `split card`：将不能共享实质核心陈述的同名异义拆成不同卡片。

AI 必须先展示建议动作和拟议差异。人类可以确认、修改或拒绝。未确认候选不进入正式知识库。正式写入前必须读取 `references/knowledge-source.yaml`，并按固定路径定位外部仓库。

## 写入完成条件

一次正式写入只有同时满足以下条件才完成：

1. 卡片位于正确目录，文件名与 frontmatter `name` 相同。
2. frontmatter 只包含 `name`、`type`、`tags` 和 `updated_at`。
3. 卡片正文满足所属类型的结构、来源和边界要求。
4. 总索引或物理索引完成索引同步；新增 tag 先登记再使用。
5. 强关系的反向关系同步更新，所有本地关系目标存在。
6. 内容变化使用本次人类维护日期更新 `updated_at`；纯格式或链接修复不更新。
7. 写入端运行 `scripts/validate_knowledge_repository.py` 并报告卡片或模板、动作、类型、tags、索引状态和验证结果。
8. 写入端报告外部知识仓库的 Git revision 与 dirty 状态，但不得自动提交。

计算模板还必须在正式晋升前记录 `calc-project` 对方法语义、集群假设和可执行验证的验收结果。

任一门禁失败、候选被拒绝或尚未确认时，结果为“不写入”，并保留原因供后续处理。
