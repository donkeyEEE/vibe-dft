# 阶段 4 — 原子性与读取检查

这一步验证卡片可被共享库安全读取，而不是测试 Skill 路由。

对每张新卡检查：

1. 文件名与 `name` 完全相同，且使用 kebab-case 和已登记前缀。
2. frontmatter 恰好包含 `name`、`type`、`tags`、`updated_at`。
3. 首段只陈述一个原子主张；需要“同时/另一方面”才能说明的独立知识对象应拆卡。
4. `type` 和 tags 均已在相应索引登记，且导航能找到该卡。
5. 通用卡以一个预期消费者任务试读；物理卡检查其核心陈述、类别必需章节、来源和关系能否独立理解。

卡片不通过时回到阶段 2 或 3，不生成 `test-prompts.json`。
